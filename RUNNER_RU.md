# Векторно-временное циклическое кодирование временных признаков для прогнозирования временных рядов

**Векторно-временное циклическое кодирование временных признаков** — подход к формированию признаков времени для многошагового прогнозирования временных рядов. Метод объединяет календарные, циклические, режимные и непрерывные признаки временной метки. В репозитории ему соответствует траектория `t2v`.

Программное обеспечение разработано **Никитой Владимировичем Саввиным** в рамках диссертационного исследования. Реализация относится к материалам **главы 2** и предназначена для вычислительных экспериментов по прогнозированию временных рядов моделями XGBoost и LSTM.

## Быстрый запуск

Все команды следует выполнять из корневого каталога репозитория.

### 1. Установка зависимостей

Проект требует Python 3.12 и PDM.

```bash
pdm install
```

### 2. Активация виртуального окружения

```bash
source .venv/bin/activate
```

Активация не обязательна, если дальнейшие команды запускаются через `pdm run`.

### 3. Проверка или подготовка данных

Файл `data/datasets_csv_dict.json` содержит пути к локальным CSV-файлам и имена временных и целевых столбцов. Он уже присутствует в репозитории. Если его необходимо создать заново вместе с локальными копиями наборов данных, выполните:

```bash
pdm run python src/data/data_config.py
```

Команда обращается к источникам данных, указанным в `src/data/data_config.py`, и сохраняет CSV-файлы в каталог `data/`.

### 4. Предварительная настройка моделей

Перед основным экспериментом необходимо получить общие параметры baseline-моделей: длину лагового окна и оптимальные гиперпараметры. Это обязательный этап, поскольку основной запуск читает эти параметры из результатов настройки и использует их без изменения для сравниваемых траекторий.

Сначала проверьте конфигурацию в `src/experiments/setup_design.py`:

- `datasets_to_test` — наборы данных;
- `models_to_exp` — модели (`LSTM`, `XGBoost`);
- `list_predict_points_to_test` — горизонты прогноза;
- `trajectories` — траектории этапа настройки; в списке обязательно должна присутствовать `baseline`.

Затем в `src/experiments/setup_main.py` задайте уникальное значение `EXPERIMENT_NAME` и при необходимости число параллельных исполнителей `WORKERS`. Запустите настройку:

```bash
pdm run python src/experiments/setup_main.py
```

Результаты будут записаны в `export/<ИМЯ_НАСТРОЙКИ>/`. Основному эксперименту необходимы файлы вида:

```text
export/<ИМЯ_НАСТРОЙКИ>/results/<набор_данных>/<модель>/<горизонт>/baseline/setups_params.csv
```

### 5. Основной эксперимент

Согласуйте конфигурации двух этапов:

1. В `src/experiments/main_design.py` выберите наборы данных, модели, горизонты и траектории. Доступны `t2v`, `baseline`, `fourier` и `rollings_stats`.
2. В `src/experiments/main.py` укажите:
   - `EXPERIMENT_NAME` — имя каталога нового основного эксперимента;
   - `SETUP_DIR_NAME` — имя каталога, созданного на этапе предварительной настройки;
   - `WORKERS` — число параллельных задач;
   - `MAX_SEARCH_ITER` — число итераций поиска признаков для траектории `t2v`.

Значение `SETUP_DIR_NAME` должно совпадать с `EXPERIMENT_NAME` из `setup_main.py`. Наборы данных, модели и горизонты основного запуска должны иметь соответствующие baseline-файлы `setups_params.csv` в каталоге настройки.

После проверки конфигурации выполните:

```bash
pdm run python src/experiments/main.py
```

## Логика проведения эксперимента

Работа состоит из двух разделённых этапов.

1. **Предварительная настройка.** `setup_main.py` определяет лаговое окно и подбирает параметры XGBoost или LSTM для каждой комбинации «набор данных — модель — горизонт». Результаты сохраняются в `setups_params.csv`.
2. **Сравнительный эксперимент.** `main.py` читает baseline-параметры и запускает все выбранные траектории при одинаковых параметрах модели и одинаковой длине лага. Благодаря этому различия метрик относятся к способу формирования временных признаков, а не к различной настройке модели.

В основном эксперименте создаются прогнозы для последних `H` точек ряда. Оцениваются MAE, MAPE, RMSE и R². Для каждой комбинации формируются прогноз, фактические значения, метрики, параметры и графики на русском и английском языках.

## Структура результатов

Для основного эксперимента результаты располагаются по схеме:

```text
export/<ИМЯ_ЭКСПЕРИМЕНТА>/
├── events.csv
├── progress_setup.csv
└── results/
    └── <набор_данных>/<модель>/<горизонт>/<траектория>/
        ├── metrics.csv
        ├── setups_params.csv
        ├── pred.csv
        ├── true.csv
        ├── <набор_данных>_<модель>_ru.png
        └── <набор_данных>_<модель>_en.png
```

- `metrics.csv` — значения MAE, MAPE, RMSE и R²;
- `setups_params.csv` — лаг, параметры модели, использованные признаки и метрики;
- `pred.csv` — прогнозные значения;
- `true.csv` — фактические значения тестового горизонта;
- `events.csv` — подробный журнал этапов выполнения основного эксперимента;
- `progress_setup.csv` — реестр завершённых конфигураций, позволяющий пропускать уже обработанные задачи при повторном запуске.

## Повторный запуск

Чтобы начать независимый эксперимент, укажите новые, ранее не использовавшиеся значения `EXPERIMENT_NAME` в `setup_main.py` и `main.py`, выполните этап настройки, после чего передайте имя его каталога в `SETUP_DIR_NAME`. Такой способ сохраняет предыдущие результаты и исключает их смешивание с новым запуском.

## Подготовка материалов для статьи

После завершения основного эксперимента таблицы и рисунки формируются скриптом:

```bash
pdm run python src/article_materials/tables.py
```

Перед запуском убедитесь, что в этом файле указан каталог нужного эксперимента. Скрипт читает метрики и прогнозы из `export/` и сохраняет материалы в русской и английской версиях.
